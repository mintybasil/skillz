# AGENTS.md

Guidance for AI agents working on this repository.

## Project Overview

**skillz** is a Rust CLI tool for managing agent skills across multiple deployments. It syncs skills from external git submodule sources into a bundle directory, with 3-way merge support for locally-modified skills.

The PRD is at `docs/PRD.md`. Read it before making changes to understand the full design.

## Repository Structure

```
src/
  main.rs       — CLI entry point (clap), command dispatch
  manifest.rs   — Manifest struct, serde, validation, save/load
  git.rs        — Git submodule operations (rev-parse, show, merge-file)
  sync.rs       — Bundle sync logic (unmodified copy, modified 3-way merge)
  report.rs     — Structured sync report output
  commands.rs   — import and lint commands, skill discovery, frontmatter parsing
  tui.rs        — Ratatui TUI for import skill selection
sources/        — Git submodules (external skill sources)
skills/         — The bundle (generated by sync, committed to repo)
  mintybasil/   — Locally-created skills (auto-included, not in manifest)
skills-manifest.yaml — Skill selections and modification metadata
docs/PRD.md     — Product requirements document
.github/workflows/ci.yml — CI (build, fmt, clippy)
```

## Build & Test

```bash
source "$HOME/.cargo/env"    # Rust toolchain is here, not in PATH by default

cargo build                          # Build
cargo test                           # Run all tests
cargo fmt --all -- --check           # Format check
cargo clippy --all-targets -- -D warnings  # Lint check
```

All four must pass before committing. CI runs build, fmt, and clippy on every PR.

## Manifest Format

```yaml
sources:
  - name: hermes-skills          # maps to submodule at sources/hermes-skills
    ref: v1.2.3                   # upstream ref (required if any skill is modified)
    base_path: skills             # optional: subdirectory in source repo where skills live
    skills:
      - path: devops/kanban       # path relative to base_path
        modified: true            # only written when true (false is default, omitted in serialization)
        mod_tags: [hermes-compat] # valid tags: hermes-compat, personalization
```

Key rules:
- `ref` is source-level, not per-skill. Updated after clean merges.
- `modified: false` is the default and is NOT serialized (skip_serializing_if).
- `mod_tags` is a fixed enum: `hermes-compat` or `personalization`. Unknown values fail at parse time.
- Same source name can appear multiple times with different `base_path` values.
- Locally-created skills go in `skills/mintybasil/` — not in the manifest.

## Sync Workflow

- **Unmodified skills**: Copied from submodule to bundle with clear-then-copy strategy.
- **Modified skills**: 3-way merge using `git merge-file`:
  - base = file at `source.ref` (from submodule git history via `git show`)
  - ours = modified file in the bundle
  - theirs = new upstream file (from current submodule working tree)
  - `ref` is only updated when ALL files in a source merge cleanly.
  - Exit code is non-zero if any conflicts occur.

## Code Conventions

- **Error handling**: `anyhow` throughout. Use `.context()` for clear messages.
- **Git operations**: Shell out to `git` CLI via `std::process::Command`, not a git crate.
- **Serialization**: serde + serde_yaml. Comments are lost on re-serialization (accepted trade-off).
- **Tests**: Use `tempfile::TempDir` for filesystem tests. Create real git repos for merge tests.
- **TUI**: ratatui + crossterm. Alternate screen buffer. Always restore terminal state on exit.
- **Field naming**: `ref_` in Rust (with `#[serde(rename = "ref")]`) since `ref` is a keyword.

## Git Workflow

- Branch naming: `feat/`, `fix/`, `refactor/`, `docs/`, `ci/` prefixes.
- Commits: conventional commits format (`feat:`, `fix:`, `refactor:`, `docs:`).
- PRs: squash merge. Include "Closes #N" to auto-close issues.
- Stacked PRs: branch off the previous feature branch, not main. Rebase after merges.
- CI must pass before merge.

## Things to Watch Out For

- **serde_yaml is deprecated** but still functional. Don't migrate unless there's a concrete need.
- **Raw mode terminal handling**: Always use `\r\n` in raw mode, or lines will drift. The TUI module handles this via ratatui's backend.
- **Submodule shallow clones**: `git show <ref>:<path>` requires the commit to be in history. Shallow clones may not have old refs needed for 3-way merge.
- **Manifest save drops comments**: serde_yaml re-serialization loses all YAML comments. This is accepted.
- **`ref` field**: Named `ref_` in Rust code with serde rename. Never use `ref` directly in Rust — it's a keyword.
